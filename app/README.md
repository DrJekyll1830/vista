# ویستا — محصول زندهٔ اثبات مفهوم

این پوشه پیاده‌سازی زندهٔ ویستاست: همان چیزی که کتاب توصیف می‌کند، در حد یک محصول قابل نمایش برای کارفرما. هر کاری که اثر دارد قرارداد دارد؛ دستیار قرارداد را می‌آورد و هرگز امضا نمی‌کند؛ اجرا در پردازشگری انجام می‌شود که دستیار به آن دسترسی ندارد.

## چه چیزی هست

| بخش | وضعیت در این نسخه |
|---|---|
| ورود با شمارهٔ موبایل و رمز یک‌بارمصرف | پیامک از پنل پیکربندی‌شده (کاوه‌نگار، sms.ir، یا هر پنل HTTP)؛ در حالت `console` کد در لاگ و رابط نشان داده می‌شود |
| تطبیق کد ملی و تاریخ تولد (شمسی) با شماره | شاهکار شبیه‌سازی‌شده — همیشه تطبیق دارد؛ کد ملی و تاریخ اعتبارسنجی می‌شوند |
| نام و نام خانوادگی | سرویس استعلام «قطع» است؛ از کاربر پرسیده می‌شود |
| قرارداد آغاز و شش اپ سیستمی | دستیار · ویترین · مالی · قراردادهای من · پشتیبانی · تنظیمات |
| کیف پول | نزد ویستا (بعداً: حساب نزد بانک سینا). شارژ = قرارداد + درگاه آزمایشی با دو دکمهٔ موفق/ناموفق |
| موتور قرارداد | پیش‌نویس → قرارداد → امضای اپ (Ed25519) → امضای کاربر → پردازشگر → رویدادها؛ هش متعارف؛ دفتر افزودنی زنجیره‌شده |
| امضا | پلهٔ ۱ (درخواست احرازشده) و پلهٔ ۲ (رمز یک‌بارمصرف گره‌خورده به هش)؛ سقف پلهٔ ۱ دو میلیون تومان |
| وکالت (از فاز دو) | سقف و انقضای اجباری، اعطا با پلهٔ ۲، بدون واگذاری، لغو یک‌طرفه، همه در یک صفحه، اطلاع بر هر مصرف |
| دروازهٔ قابلیت | اتصال MCP (Streamable HTTP و SSE)، مانیفست `vista://manifest`، فقط خواندن و ساختن قرارداد منتشر می‌شود، سلامت دوره‌ای |
| ویترین | چهار MCP غیرملی (GitHub، DeepWiki، Hugging Face، Cloudflare Docs) + اپ نمونهٔ مرجع؛ افزودن اپ با آدرس |
| اپ نمونهٔ مرجع | «خدمات ایرانسل (نمونه)» — شارژ، بسته، قبض، وکالت تمدید خودکار، مینی‌اپ؛ شبیه‌سازی‌شده |
| دستیار | رابط سازگار با OpenAI؛ حلقهٔ ابزار روی دروازه؛ استریم؛ «کلید خودت را بیاور»؛ بدون مدل، خاکستری می‌شود و بقیه کار می‌کنند |
| فوروارد به دستیار، اشتراک‌گذاری با لینک، اعتراض | هست |
| اسکیل برای اپ‌های شریک (کنکوریا) | `../skills/vista-app/` — مشخصات + کتابخانهٔ امضا + آزمون انطباق |

## اجرا

```bash
cd app
cp .env.example .env        # و مقادیر را پر کنید (پایین را ببینید)
pnpm install
pnpm build                  # سرور + وب‌کلاینت
pnpm start                  # http://localhost:8787
```

برای توسعه: `pnpm dev` (سرور روی ۸۷۸۷ و Vite روی ۵۱۷۳ با پراکسی). نیازمندی: Node ≥ 22.13 (SQLite داخلی Node؛ هیچ وابستگی بومی ندارد).

## پیکربندی (فایل `.env`)

- **پیامک**: `SMS_PROVIDER=kavenegar` با `KAVENEGAR_API_KEY` (و اختیاری `KAVENEGAR_TEMPLATE` برای الگوی تأیید)، یا `smsir` با `SMSIR_API_KEY` و `SMSIR_TEMPLATE_ID`، یا `http` با `SMS_HTTP_URL`/`SMS_HTTP_BODY` که در آن `{phone}` و `{message}` جایگزین می‌شوند. تا پنل وصل نشده: `SMS_PROVIDER=console` و اگر لازم شد `OTP_ACCEPT_ANY=true`.
- **مدل زبانی**: `AI_BASE_URL` (آدرس پایهٔ سازگار با OpenAI، مثل `https://.../v1`)، `AI_API_KEY`، `AI_MODEL`. هر کاربر می‌تواند در تنظیمات کلید خودش را بگذارد.
- **آدرس عمومی**: `PUBLIC_URL` — برای لینک‌های اشتراک‌گذاری، مینی‌اپ و آدرس MCP اپ نمونه.
- **درگاه**: `PAYMENT_GATEWAY=fake` — بعداً درگاه واقعی جایگزین می‌شود (`contracts/system.ts › completeTopup` نقطهٔ اتصال است).
- **احراز هویت**: `SHAHKAR_PROVIDER=mock` و `NAME_LOOKUP_PROVIDER=down` — سرویس واقعی در `auth/service.ts` وصل می‌شود.

## آزمون

```bash
node scripts/e2e.mjs                                   # جریان کامل از ورود تا وکالت، روی سرور در حال اجرا
node ../skills/vista-app/scripts/conformance.mjs http://localhost:8787/apps/irancell-demo/mcp
```

## ساختار

```
server/src
  auth/        ورود، رمز یک‌بارمصرف، احراز هویت (شاهکار، نام)
  contracts/   مدل، هش متعارف، کلیدها، موتور (امضا، پردازشگر، رویدادها)، قراردادهای سیستمی، وکالت
  wallet/      کیف پول: شارژ، مسدودی، کسر، بازگشت
  gateway/     ثبت اپ‌ها و ویترین، کلاینت MCP، طبقه‌بندی ابزارها، سلامت
  assistant/   رابط مدل و حلقهٔ دستیار
  chats/       گفت‌وگوها و پیام‌ها (قرارداد و رویداد هم پیام‌اند)
  sample-app/  اپ نمونهٔ مرجع (سرور MCP + مینی‌اپ)
  routes/      API، رابط اپ‌ها، صفحهٔ درگاه آزمایشی
  ledger.ts    دفتر افزودنی زنجیره‌شده
web/src        وب‌کلاینت (React): ورود، احراز، فهرست اپ‌ها، گفت‌وگو، قرارداد، ویترین، مالی، قراردادها، وکالت‌ها، تنظیمات
```

## آنچه عمداً نیست

پله‌های ۳ و ۴ امضا (کلید گوشی و سیم‌کارت)، کیف پول نزد بانک، درگاه واقعی، شاهکار واقعی، و اتصال به سامانه‌های ملی. هر کدام نقطهٔ اتصال مشخصی در کد دارد و با پیکربندی یا یک ماژول جایگزین می‌شود.
