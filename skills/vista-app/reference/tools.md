# ابزارهای MCP — خواندن، ساختن، تحویل

اپ ویستا یک سرور MCP است که سه دسته ابزار دارد و مانیفست می‌گوید هر ابزار در کدام دسته است: **خواندنی** (رایگان، بی‌قرارداد)، **ساختن قرارداد** (سند امضاشده برمی‌گرداند)، و **تحویل** (پنهان؛ فقط پردازشگر). هر ابزار دیگری پنهان می‌شود. این سند قرارداد دقیق هر دسته، ترابری، و آنچه در `_meta` می‌آید را می‌گوید.

## ترابری و دسترسی

- **Streamable HTTP** (مشخصات MCP ۲۰۲۵): یک آدرس، مثل `https://api.konkooria.ir/vista/mcp`، که `POST` با JSON-RPC می‌پذیرد و با JSON یا SSE پاسخ می‌دهد. ویستا اول این را امتحان می‌کند و اگر نشد، ترابری قدیمی SSE را. Streamable HTTP را بسازید.
- **بی‌نشست کافی است**: برای هر درخواست یک `McpServer` و یک transport تازه با `sessionIdGenerator: undefined` (نمونه در `lib/example-server.mjs`). ویستا نشست را نگه می‌دارد اگر بدهید، اما لازم ندارد.
- **دسترس‌پذیری**: سرور ویستا (نه مرورگر کاربر) به این آدرس وصل می‌شود؛ پس باید از اینترنت (یا شبکهٔ توافق‌شده) در دسترس باشد، HTTPS با گواهی معتبر داشته باشد، و پشت احراز هویتی نباشد که ویستا نمی‌شناسد. ویستا با `user-agent: vista-gateway/0.1` می‌آید.
- **احراز هویت اختیاری**: اگر برای اپ‌تان توکن لازم است، ویستا می‌تواند هنگام نصب از کاربر یک credential بگیرد و در هدر `authorization: Bearer <token>` (یا هدری که در رجیستری برای اپ تنظیم شده) بفرستد. برای اپ ویستایی معمولاً لازم نیست: هویت کاربر از `_meta.vista` می‌آید و امنیت از امضاها.
- **اتصال‌ها ۵ دقیقه نگه داشته می‌شوند**؛ سرور را طوری بنویسید که اتصال‌های بیکار را مشکل نداند.

## بازبینی سلامت

ویستا هر ۵ دقیقه (و هنگام افزودن/نصب) اپ را می‌سنجد: `initialize` → `tools/list` → `resources/read vista://manifest`. اگر هر کدام خطا دهد، `health: 'down'` می‌شود: اپ در فهرست کم‌رنگ می‌شود و **قراردادهایش قابل امضا نیستند** («این اپ در دسترس نیست»). پس این سه فراخوانی باید همیشه سریع و بدون وابستگی به پایگاه دادهٔ سنگین جواب دهند. یک مسیر `/health` ساده هم برای مانیتورینگ خودتان بگذارید.

## بافت ویستا در `_meta.vista`

هر فراخوانی ابزار خواندنی یا ساختن، از طرف یک کاربر مشخص است. ویستا هویت او را در `params._meta.vista` می‌فرستد:

```json
{
  "user_id": "user:usr_v2kqzs0nybxn61np",
  "user_ref": "u_zs0nybxn61",
  "phone": "09121234567",
  "name": "سارا محمدی"
}
```

- شناسهٔ `user_id` همیشه هست؛ با پیشوند `user:`. **همین رشته** شناسهٔ طرف کاربر در قرارداد است.
- شبه‌نام `user_ref` همیشه هست؛ شبه‌نام پایدار (`u_` + ده نویسهٔ آخر شناسه). کلید مناسب برای ذخیرهٔ وضعیت کاربر در بک‌اند شما، بدون نگه داشتن شناسهٔ خام.
- شمارهٔ `phone` فقط اگر مانیفست `data_permissions: ['profile.phone']` را اعلام کرده **و** کاربر مجوز `profile.read` را داده باشد. همین‌طور `name` با `profile.name`. در غیر این صورت این کلیدها **اصلاً وجود ندارند**. کد شما باید بدون آن‌ها کار کند.
- در ابزار تحویل `_meta` **نمی‌آید**؛ کاربر را از `contract.parties` (طرف با `kind: 'user'`) بردارید.

با SDK رسمی:

```js
server.registerTool('get_study_plan', { /* … */ }, async (args, extra) => {
  const v = extra?._meta?.vista;
  if (!v?.user_id) return { content: [{ type: 'text', text: 'vista context missing' }], isError: true };
  const ref = v.user_ref; // کلید کاربر در بک‌اند شما
  // …
});
```

نگاشت کاربر ویستا به کاربر خودتان: با `user_ref` (یا اگر مجوز دارید، `phone`). اگر کاربر ویستا هنوز حساب کنکوریا ندارد، ابزار خواندنی می‌تواند «حساب یافت نشد؛ برای اتصال، شماره را در مینی‌اپ تأیید کنید» برگرداند؛ اتصال حساب خودش هم می‌تواند یک قرارداد بدون پول باشد (`app.action` تنها).

## ابزارهای خواندنی (`tools.read`)

- حاشیه‌نویسی `annotations: { readOnlyHint: true }` بگذارید (ویستا از مانیفست تصمیم می‌گیرد، اما annotation برای کلاینت‌های دیگر و برای وضوح لازم است).
- هیچ اثری نداشته باشند: نه رزرو، نه لاگ رفتاری که وضعیت را عوض کند، نه ارسال پیامک.
- ورودی با `inputSchema` دقیق (zod)؛ مقادیر اختیاری را اختیاری کنید تا دستیار بی‌جهت نپرسد.
- خروجی: `content: [{ type: 'text', text: JSON.stringify(obj) }]` — JSON فشرده، کلیدهای لاتین، برچسب‌های فارسی در مقدارها، مبالغ عددی به تومان با پسوند `_toman`. `structuredContent` هم پذیرفته می‌شود.
- کوتاه: دستیار خروجی را می‌خواند و در گفت‌وگو تا ۱۵۰۰ نویسه نشان داده می‌شود. فهرست‌های بلند را صفحه‌بندی کنید (`limit`, `offset`).
- **اپ برگ است**: خروجی فقط داده است. هرگز جمله‌ای خطاب به دستیار یا کاربر با فعل امری ننویسید («حالا قرارداد بساز»). اگر گام بعدی طبیعی هست، آن را به‌صورت داده بگویید: `"next": "build_course_enrollment_contract"`.
- خطا: `{ content: [{ type: 'text', text: 'پیام فارسی' }], isError: true }`.

## ابزارهای ساختن قرارداد (`tools.build`)

قرارداد ابزار ساختن با ویستا این است:

**ورودی**: آرگومان‌های خودتان + `_meta.vista`. اسکیما را سخت‌گیر کنید: شناسه‌ها به‌صورت `z.enum([...])` وقتی فهرست کوتاه است، مبالغ با `min/max`، و `describe()` فارسی برای هر فیلد. آنچه دستیار نمی‌داند را از ابزار خواندنی می‌گیرد؛ ابزار ساختن نباید حدس بزند.

**خروجی موفق**: یک `text` که JSON این شکل است (یا همان در `structuredContent`):

```json
{ "contract": { …ContractDoc… }, "canonical_hash": "c4dbec5d…", "app_signature": "MN1k+RtT…" }
```

ویستا آن را پارس می‌کند، `createContract` را اجرا می‌کند (اعتبارسنجی، یکتایی، امضا با کلید مانیفست)، و قرارداد را با وضعیت `awaiting` در گفت‌وگوی اپ به کاربر نشان می‌دهد. اگر ثبت رد شود، خطای ویستا (جدول در `contract.md`) به دستیار برمی‌گردد و کاربر پیام آن را می‌بیند.

**خروجی خطا**: `isError: true` با پیام فارسی روشن: «بسته یافت نشد»، «ظرفیت دوره تکمیل است»، «برای ساخت قرارداد، شمارهٔ دانش‌آموزی لازم است». دستیار این را به کاربر می‌گوید و اگر داده‌ای کم است می‌پرسد.

قاعده‌ها:

- **بدون اثر جانبی.** ساختن قرارداد یعنی محاسبه + امضا. ظرفیت را رزرو نکنید، سفارش نسازید، پیامک نفرستید. اگر ناچار به رزرو موقت هستید، آن را دقیقاً تا `expires_at` سند نگه دارید و اگر تحویل نیامد رها کنید.
- **عدد از شما می‌آید.** قیمت، تخفیف و مالیات را از بک‌اند خودتان بخوانید، نه از آرگومان دستیار. آرگومان «مبلغ» فقط وقتی معنا دارد که کاربر واقعاً آن را انتخاب می‌کند (مثل شارژ)؛ حتی آن‌جا با `min/max` مهارش کنید.
- **هر بار سند تازه.** `id` و `nonce` تازه، `created_at` اکنون، `expires_at` ۱۵ دقیقه بعد. سند را کش نکنید.
- **`app_id` = شناسهٔ ثبت‌شده نزد ویستا**؛ `payee_app_id` هم همان.
- **کاربر = `_meta.vista.user_id`** با `must_sign: true`. برچسب: `name` اگر هست، وگرنه «شما».
- **بندها را برای انسان بنویسید**: موضوع، جزئیات خدمت، مبلغ (`kind: 'amount'`)، تحویل و زمان کسر پول، بازگشت وجه/لغو.
- `wallet.pay` + `app.action` را با هم بگذارید تا تحویل، پارامترهای خدمت را در خودِ قرارداد داشته باشد.
- در وصف ابزار (description) بنویسید چه قراردادی می‌سازد؛ ویستا خودش عبارت «(قرارداد می‌سازد؛ کاربر امضا می‌کند)» را به آن اضافه می‌کند.
- `readOnlyHint` نگذارید (یا `false`).

نمونهٔ کامل در `lib/example-server.mjs` (`build_order_contract`) و در `konkooria-example.md`.

## ابزار تحویل (`tools.fulfil`)

یک ابزار، معمولاً به نام `vista_fulfil`. ویستا آن را از دستیار و کاربر **پنهان** می‌کند و فقط پردازشگر، پس از اجرای موفق قرارداد، صدایش می‌زند.

**ورودی**:

```json
{
  "contract": { …ContractDoc کامل، همان که کاربر امضا کرد… },
  "platform_signature": "<base64 Ed25519 سکو روی رشتهٔ 'executed|<canonical_hash>'>",
  "delegation_id": "dlg_…"   // فقط اگر این قرارداد وکالت داده یا زیر وکالت اجرا شده
}
```

بافت `_meta` ندارد؛ credential کاربر (اگر اپ توکن می‌خواهد) در هدر می‌آید.

**بررسی‌های واجب**:

1. هش را خودتان حساب کنید: `hash = contractHash(contract)`.
2. امضای سکو را روی `executed|<hash>` با کلید عمومی سکو بسنجید (`verifyPlatformExecuted`). کلید را از `GET <VISTA_URL>/api/platform` بخوانید و کش کنید. امضای نامعتبر → `isError` با `{ events: [{ type: 'failed', text: 'امضای سکو معتبر نیست' }] }`. این تنها چیزی است که ثابت می‌کند پول واقعاً مسدود/کسر شده است؛ هرگز بدون آن تحویل ندهید.
3. `contract.app_id` مالِ شماست.
4. **idempotency**: با `contract.id` بررسی کنید قبلاً تحویل داده‌اید یا نه. ویستا اگر `delivered` نگیرد، هر دقیقه دوباره صدا می‌زند؛ و اگر شبکه قطع شود، دوباره صدا می‌زند. اگر قبلاً تحویل داده‌اید، همان `delivered` را دوباره برگردانید (سکو کسر را دو بار انجام نمی‌دهد).

**خروجی**: متن JSON

```json
{ "events": [ { "type": "delivered", "text": "دسترسی به دوره فعال شد", "payload": { "course_id": "math-101" } } ] }
```

انواع مجاز برای اپ و اثرشان:

| رویداد | معنا | اثر در سکو |
|---|---|---|
| `delivered` | خدمت تحویل شد | `on_delivery`: مسدودی کسر می‌شود (`deducted`)؛ وضعیت `settled` |
| `cancelled` | اپ نتوانست/نخواست تحویل دهد | مسدودی آزاد؛ وضعیت `cancelled` |
| `failed` | خطای اجرا | مسدودی آزاد؛ وضعیت `failed` |
| `refunded` | بازگشت وجه (پس از تحویل) | مبلغ (`payload.amount` یا کل) به کیف پول برمی‌گردد؛ وضعیت `refunded` |
| `note` | یادداشت؛ بدون اثر مالی | فقط در گفت‌وگو نمایش داده می‌شود |

هر رویداد در گفت‌وگوی اپ به‌صورت پاسخ به همان قرارداد ظاهر می‌شود؛ `text` کوتاه و فارسی بنویسید.

**خطای گذرا در برابر خطای قطعی**: ویستا هر پاسخ `isError` از ابزار تحویل (و هر رویداد `failed`) را **قطعی** می‌گیرد: مسدودی آزاد و قرارداد `failed` می‌شود و دیگر تلاش نمی‌کند. پس برای مشکل گذرا (پایگاه داده در دسترس نیست، کلید سکو هنوز خوانده نشده، صف پر است) هرگز `isError` ندهید؛ پاسخ عادی `{ "events": [] }` یا `{ "events": [{ "type": "note", "text": "…" }] }` برگردانید تا سکو هر دقیقه دوباره بپرسد. فقط وقتی مطمئنید تحویل هرگز ممکن نیست (امضای جعلی، کالای حذف‌شده)، `failed` یا `cancelled` بدهید. اگر سرور شما اصلاً پاسخ ندهد (قطع شبکه، ۵۰۰)، سکو یادداشت «اپ در لحظهٔ اجرا پاسخ نداد؛ دوباره تلاش می‌شود» می‌گذارد و بعداً دوباره می‌پرسد.

**تحویل دیرهنگام**: اگر تحویل لحظه‌ای نیست (مثلاً کارشناس باید تأیید کند)، `{ events: [{ type: 'note', text: 'در صف بررسی' }] }` برگردانید و بعداً `delivered` را با `POST /api/app-events` بفرستید (`events-and-delegation.md`). تا آن وقت پول مسدود می‌ماند و سکو هر دقیقه دوباره ابزار تحویل را صدا می‌زند؛ به همان `note` (یا خالی) پاسخ دهید.

**زمان**: پاسخ در چند ثانیه. کار سنگین را در صف بگذارید و `note` بدهید.

## آنچه نباید منتشر شود

- هیچ ابزاری با اثر: `create_order`, `enroll_user`, `charge`, `send_sms`, `update_profile`, `delete_*`. در ویستا این‌ها وجود ندارند؛ اثر فقط از راه قرارداد + تحویل می‌آید. اگر چنین ابزارهایی برای کلاینت‌های دیگر دارید، در مانیفست اعلامشان نکنید (ویستا پنهانشان می‌کند) یا بهتر، سرور MCP جداگانه برای ویستا بسازید.
- ابزار تحویل در `read` یا `build`.
- ابزاری که کد یک‌بارمصرف، رمز، یا شمارهٔ کارت می‌گیرد.
- ابزاری که چیزی از کاربر «تأیید» می‌گیرد؛ تأیید = امضا = فقط در ویستا.

## نام‌گذاری

- خواندنی: `get_*`, `list_*`, `search_*`, `check_*`
- ساختن: `build_*_contract`, `build_*_delegation`
- تحویل: `vista_fulfil`
- `title` فارسی کوتاه؛ `description` فارسی یک‌جمله‌ای که بگوید چه می‌دهد و واحد مبلغ چیست («تومان»).

## آزمون

```bash
node scripts/conformance.mjs https://api.konkooria.ir/vista/mcp
node scripts/conformance.mjs https://api.konkooria.ir/vista/mcp --tool build_course_enrollment_contract --args '{"course_id":"math-101"}'
node scripts/conformance.mjs http://localhost:8790/mcp --platform-key <b64> --platform-private-key platform.pem   # آزمون مثبت تحویل با کلید آزمایشی خودتان
```

اسکریپت مستقیم با MCP حرف می‌زند، مانیفست و ابزارها را می‌سنجد، یک قرارداد می‌سازد، هش و امضا را بازمحاسبه می‌کند، و بررسی می‌کند ابزار تحویل امضای جعلی سکو را رد کند.
